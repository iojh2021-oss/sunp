# SunP — شبیه‌ساز چرخه حیات، زودیاک و درخت حیات

پروژه یک شبیه‌ساز گسسته و قابل بازتولید است. هسته‌ی تصمیم‌گیری و تعاملات زیستی از گرافیک جداست؛ Canvas فقط وضعیت واقعی مدل را نشان می‌دهد. واحدها فرضی‌اند و این مدل بازسازی علمی زمین یا خورشید یا ادعای عرفانی واقعی نیست؛ یک استعاره‌ی نمادین و قابل آزمایش است.

## چرخه‌ی اصلی (مطابق عکس مرجع)

نور خورشید ← ذره نور ← بذر ← جوانه ← گیاه ← درخت ← گل و میوه ← موجود زنده ← تولیدمثل ← بازگشت به خاک ← چرخه دوباره (∞)

- **تولد:** خورشید ذره‌ی نور می‌فرستد؛ هر ۶ ذره در خاکِ مناسب یک بذر می‌سازد. موجودات بالغ هم با شرط سلامت/انرژی/منابع تولیدمثل می‌کنند.
- **رشد و چالش:** موجودات مراحل بذر ← جوانه ← گیاه ← بالغ ← گل و میوه ← پیری را طی می‌کنند و با چالش‌های خشکسالی، سرمای شدید، گرمای شدید، توفان، بیماری گیاهی و سیل روبه‌رو می‌شوند. هر موجود تاب‌آوری و تجربه دارد؛ بقا در چالش‌ها هر دو را بالا می‌برد و فرزندان بخشی از تاب‌آوری والد را به ارث می‌برند.
- **بازگشت:** در پایان عمر، مواد به خاک و انرژی و «تجربه» به خورشید برمی‌گردد.
- **خورشید یادگیرنده:** ترکیبی از چند لایه است — جدول ارزش به‌ازای وضعیت (آرامش/هر چالش)، یک شبکه‌ی عصبی کوچک که همان لحظه در مرورگر با هر گام آموزش می‌بیند (replay اولویت‌دار)، سیگنال مشورتی اختیاری عامل‌های کمکی (BrainCog/Hyperon، فقط پیشنهاد — تصمیم نهایی همیشه با خورشید است)، و در صورت وجود، یک سیاست PPO عمیق‌تر با **حافظه‌ی بلندمدت (LSTM)** که آفلاین با PyTorch آموزش دیده (`training/train_ppo.py`) و در `public/models/sun-ppo.json` بارگذاری می‌شود. حافظه‌ی LSTM (`sun.rlHidden`) هم مثل بقیه‌ی حافظه‌ی خورشید ذخیره و بازیابی می‌شود، پس با گذر زمان واقعاً «روی تجربه‌ی بلندمدت» تصمیم می‌گیرد، نه فقط وضعیت لحظه. تصمیم نهایی ترکیب شفاف این منابع است (`getSunDecisionReport`).
- **رشد و دنیای بهتر:** تجربه‌ی انباشته سطح خورشید را در درخت حیات (ملکوت ← کتر) بالا می‌برد؛ هرچه خورشید باتجربه‌تر شود، موجودات تازه قوی‌تر متولد می‌شوند و چالش‌ها ضعیف‌تر اثر می‌گذارند. رسیدن به کتر = یک «چرخه خرد» و شروع دوباره از ملکوت، بدون از دست دادن آموخته‌ها.
- **زودیاک و درخت حیات:** ۱۲ نشان (هر ۳۰ روز مدل) نور/دما/آب را تغییر می‌دهد؛ ۱۰ سفیروت، ۳ ستون (رحمت/سختی/تعادل) و ۲۲ مسیر وضعیت رشد خورشید را نشان می‌دهند.
- **۱۲ موجود زودیاک:** با فرارسیدن هر نشان (قوچ🐏، گاو🐂، دوقلوها👯، خرچنگ🦀، شیر🦁، خوشه گندم🌾، ترازو⚖️، کژدم🦂، کمانگیر🏹، بز کوهی🐐، آبریز🏺، ماهی🐟)، یک موجود همان نشان هم از نور خورشید متولد می‌شود؛ نقش‌های اکولوژیک متفاوتی دارند (تولیدکننده، مصرف‌کننده، شکارچی، تجزیه‌کننده) و در زنجیره‌ی غذایی با گونه‌های پایه ترکیب می‌شوند.

## حافظه‌ی ماندگار

آنچه ذخیره می‌شود: جدول ارزش سیاست‌ها، تعداد دفعات آزمودن هر سیاست، سطح و XP خورشید، چرخه‌های خرد، مجموع تجربه‌ی برگشتی، شارژ ستون‌ها و آمار کلی. با «جهان جدید» فقط جهان تازه شروع می‌شود و حافظه می‌ماند.

- **بدون سرور (مثلاً GitHub Pages):** در `localStorage` مرورگر ذخیره می‌شود.
- **با سرور:** در `data/memory.json` روی سرور ذخیره می‌شود و همه‌ی بازدیدکنندگان یک خورشید مشترک را می‌بینند.

## اجرا روی سرور

```sh
npm test                 # آزمون‌های موتور
npm run test:server      # آزمون‌های سرور و API حافظه
npm start                # http://localhost:8080
```

متغیرهای محیطی (همه اختیاری):

| متغیر | کاربرد |
|---|---|
| `PORT` / `HOST` | پورت و آدرس شنود (پیش‌فرض 8080 و 0.0.0.0) |
| `SUNP_DATA_DIR` | پوشه‌ی داده (پیش‌فرض `./data`؛ روی هاست حتماً روی دیسک پایدار باشد) |
| `SUNP_TOKEN` | اگر تنظیم شود، ذخیره/پاک‌کردن حافظه نیازمند `Authorization: Bearer <token>` است. یک بار صفحه را با `#token=<token>` باز کنید تا مرورگر به خاطر بسپارد. |
| `SUNP_AUTORUN=1` | خود سرور هم بدون مرورگر شبیه‌سازی را اجرا می‌کند و خورشید همیشه در حال یادگیری است |
| `SUNP_TICK_MS` | فاصله‌ی گام‌ها در حالت autorun (پیش‌فرض 1000) |

API: `GET /api/memory` · `PUT /api/memory` · `DELETE /api/memory` · `GET /api/health`. حافظه‌ی قدیمی‌تر (کمتر گام) هرگز روی جدیدتر نمی‌نشیند (۴۰۹) و ورودی‌ها اعتبارسنجی و محدود می‌شوند.

## فایل‌ها

- `src/simulation.js`: موتور (اکوسیستم با ۱۹ گونه شامل ۱۲ موجود زودیاک، ۶ نوع چالش، خورشید یادگیرنده سه‌لایه، زودیاک، درخت حیات، حافظه)
- `src/scene.js`: صحنه‌ی Canvas با آیکون موجودات، ذره‌های نور و بازگشت انرژی
- `src/main.js`: داشبورد، کنترل‌ها و ذخیره/بازیابی حافظه
- `server.js`: سرور بدون وابستگی + API حافظه + autorun اختیاری
- `training/`: آموزش آفلاین سیاست PPO با PyTorch (`train_ppo.py`) روی موتور واقعی JS (`sunp_bridge.js`)؛ خروجی در `public/models/`
- `tests/`: آزمون‌های موتور و سرور
