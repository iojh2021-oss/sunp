# بررسی اتصال BrainCog و OpenCog Hyperon به SunP
تاریخ بررسی: 2026-09-29

## دامنه
این یادداشت ارزیابی سازگاری است؛ وابستگی‌ها عمداً به SunP اضافه نشده‌اند و هیچ موتور موجودی جایگزین نشده است. هدف حفظ شبیه‌ساز JavaScript فعلی و بررسی امکان افزودن سرویس شناختی اختیاری است.

## وضعیت فعلی SunP
- موتور اصلی در `src/simulation.js` با JavaScript و ES modules است.
- رابط `src/main.js` در مرورگر اجرا می‌شود؛ استقرار GitHub Pages فقط فایل‌های ایستا را منتشر می‌کند.
- `server.js` یک سرور Node بدون وابستگی و API حافظه دارد؛ می‌تواند بعداً نقش درگاه محلی به سرویس شناختی را بگیرد.
- عامل/خورشید فعلی شامل ارزش‌گذاری سیاست‌ها، شبکه کوچک قابل‌آموزش در مرورگر و سیاست PPO آفلاین با PyTorch است.
- آموزش PPO فعلی از Python، Gymnasium, TorchRL/TensorDict و Node bridge استفاده می‌کند.
- آزمون‌های فعلی: `npm test`؛ تست سرور: `npm run test:server`.
- در ریشهٔ مخزن فایل `LICENSE` در مسیر استاندارد یافت نشد؛ مجوز SunP را پیش از ادغام کد خارجی باید مشخص کرد.

## BrainCog
منبع: https://github.com/BrainCog-X/Brain-Cog
مستندات نصب: https://brain-cog.network/docs/tutorial/1_installation.html
- ماهیت: چارچوب شبکه‌های عصبی اسپایکی و الگوریتم‌های شناختی/یادگیری؛ بیشتر یک جعبه‌ابزار پژوهشی عصبی است تا عامل گفت‌وگویی و برنامه‌ریز آماده.
- مجوز: مخزن GitHub شامل فایل LICENSE و نشان MIT در نمای مخزن است؛ پیش از توزیع مشتق، متن LICENSE و مجوز داده‌ها/مدل‌های جداگانه بازبینی شود.
- وابستگی‌های اعلام‌شده: Python (مستندات نسخه 3.8)، PyTorch، torchvision، torchaudio، NumPy، SciPy، h5py، timm، einops، matplotlib و بسته‌های مرتبط؛ برخی مسیرهای شبیه‌سازی/آموزش به CUDA و داده‌های خاص نیاز دارند.
- اجرا: نصب با pip یا نصب editable از مخزن مستند شده؛ اما نصب پایه به معنی آماده‌بودن همه مثال‌ها روی CPU/سرور SunP نیست. باید محیط جداگانه و آزمون نصب واقعی انجام شود.
- اتصال به SunP: از طریق سرویس Python جدا و API JSON. موتور JS وضعیت جهان و قوانین را نگه می‌دارد؛ BrainCog تنها بردار مشاهده/پاداش را می‌گیرد و پیشنهاد عمل می‌دهد. تبدیل مستقیم کل جهان به شبکه نورونی توصیه نمی‌شود.

## OpenCog Hyperon / MeTTa
منابع:
- https://github.com/trueagi-io/hyperon-experimental
- https://pypi.org/project/hyperon/
- https://hyperon-tutorials.readthedocs.io/en/latest/getting_started/installation.html
- https://hyperon.opencog.org/
- ماهیت: محیط شناختی/نمادین و زبان MeTTa برای بازنمایی دانش و استنتاج؛ مکمل مدل عصبی است، نه جایگزین شبیه‌ساز.
- وضعیت بلوغ: بسته PyPI در مرحله pre-alpha معرفی شده؛ API و دستورهای ساخت ممکن است تغییر کنند. راهنمای build از Rust/Cargo و CMake نام می‌برد؛ پشتیبانی ساخت Windows در مستندات آموزشی کامل نیست.
- مجوز: بسته PyPI مجوز MIT را اعلام می‌کند؛ مجوز تمام اجزای وابسته و فایل‌های مخزن/نسخه انتخابی قبل از ادغام باید بررسی شود.
- اتصال به SunP: قابل آزمایش از طریق Python binding/فرایند جدا؛ دانش را می‌توان به شکل گزاره‌ها/روابط (مثلاً گونه X از منبع Y تغذیه می‌کند) نمایش داد و پاسخ استنتاجی را به لایه برنامه‌ریز تحویل داد. هیچ اتصال آماده‌ای به ساختار فعلی SunP وجود ندارد.

## ارزیابی سازگاری
| معیار | BrainCog | Hyperon |
|---|---|---|
| مناسب برای | یادگیری/تصمیم‌گیری عصبی اسپایکی | دانش، قواعد و استنتاج نمادین |
| اجرای مستقیم در GitHub Pages | خیر | خیر |
| نیاز به Python/Rust runtime | Python و PyTorch | MeTTa runtime؛ bindingهای Python/Rust |
| اتصال به کد فعلی | سرویس Python با ورودی/خروجی عددی | سرویس/ماژول MeTTa با ورودی/خروجی ساخت‌یافته |
| ریسک اصلی | وابستگی‌های سنگین، GPU و انتقال از نمونه پژوهشی به عامل محیطی | بلوغ pre-alpha، تغییر API و نیاز به مدل‌سازی دانش |
| پیشنهاد | نمونهٔ آزمایشی مستقل؛ نه جایگزینی PPO فعلی | نمونهٔ کوچک برای قواعد و حافظهٔ دانشی |

## معماری پیشنهادی کم‌ریسک
1. حفظ `src/simulation.js` به‌عنوان مرجع نهایی وضعیت و قوانین جهان.
2. تعریف قرارداد نسخه‌دار `observation → proposal → validation → action → reward` در Node؛ عامل حق تغییر مستقیم وضعیت جهان را نداشته باشد.
3. ابتدا یک adapter ساده و mock در Node بسازیم و تست کنیم؛ بعد BrainCog و Hyperon را جداگانه پشت همان قرارداد قرار دهیم.
4. BrainCog فقط برای یک وظیفه محدود (مثلاً طبقه‌بندی وضعیت/پیشنهاد سیاست) آزمایش شود؛ PPO فعلی به‌عنوان baseline باقی بماند.
5. Hyperon برای ذخیره و استنتاج چند قانون اکولوژیک نمونه آزمایش شود؛ خروجی آن پیشنهاد باشد و با اعتبارسنجی قوانین SunP کنترل شود.
6. اجرای واقعی عامل‌ها روی سرور جدا یا محیط محلی باشد. GitHub Pages صرفاً UI را نشان دهد و از API سرور استفاده کند. کلیدها و مجوزهای پژوهش وب هرگز در کد مرورگر قرار نگیرند.
7. پیش از ادغام نهایی: تست CPU نصب، آزمون API، benchmark با seedهای یکسان، مقایسه سلامت/تنوع/پایداری و تست بازگشت به سیاست قبلی.

## نتیجه
هیچ‌یک را فعلاً نباید به‌عنوان «مغز آماده» داخل SunP کپی کرد. BrainCog برای آزمایش یادگیری عصبی و Hyperon برای استدلال دانشی دو مکمل متفاوت‌اند. مرحله بعد باید یک نمونه اتصال حداقلی و قابل خاموش‌کردن باشد؛ ادغام هم‌زمان هر دو یا حذف PPO فعلی پیش از benchmark توصیه نمی‌شود.
